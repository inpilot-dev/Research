# 검증 로직은 LLM 밖의 결정론적 스크립트에 두고, 스킬은 얇은 래퍼로 한다

L1(출처 존재)·L2(원문 대조)·순환보고 dedup은 `scripts/`의 순수 코드로 구현하고 SKILL.md는 그것을 호출만 한다. 프롬프트에 검증 절차를 쓰는 쪽이 빠르지만, 모델이 무시할 수 있고 재현이 안 되며 현장에서 코드를 열어 보일 수 없다 — nagomi가 "GRADE"라 광고한 것이 코드를 열자 저널명 하드코딩+정규식이었던 것이 반례다(research/08). 결정론적 코어는 테스트가 붙고, CLI로 그대로 재사용되며(argparse 하나), 같은 입력에 같은 결과를 낸다. L3(의미적 뒷받침)만 LLM을 쓰며 기본값이 아니라 옵션(`--deep`)이다.

## Considered Options

- 프롬프트 전용 스킬(Scriptorium 외 대부분의 research 스킬 방식) — 기각: 재현 불가, 검증 불가, 모델이 절차를 건너뛸 수 있음.
- 검증까지 LLM-judge에 위임 — 기각: 인용 환각률이 도메인별 14~95%로 편차가 커(research/15) 판정기 자체를 신뢰할 수 없음.
