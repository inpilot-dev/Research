# 스킬팩 기획 — "어느 출처든 끝까지 뚫고 가서 읽는다" (Claude Code + Codex)

2026-09-07. 브레인스토밍 재개 + 접근(페치) 층 기획. 근거: [13 접근 도구](13-access-tools.md) · [15 실패모드 §6](15-failure-modes.md) · [16 종합](16-synthesis-research-agent.md) · ADR [0001](../docs/adr/0001-deterministic-verification-core.md)~[0003](../docs/adr/0003-no-output-without-verification-gate.md) · spec [#1](https://github.com/inpilot-dev/Research/issues/1) · 티켓 #2~#8.

## 0. 한 줄

이 스킬팩은 새 제품이 아니라 **verify 파이프라인의 접근(페치) 층**이다. "뚫고 간다"는 것은 사다리를 끝까지 올라간다는 뜻이고, 마지막 칸은 항상 **사람에게 넘기며 방안을 말해주는 것**이다. 에이전트는 **어떤 경우에도 사용자의 비밀번호를 읽거나 보유하지 않는다.**

## 1. 기존 결정과의 정합 — 어느 층인가

| 층 | 담당 | 상태 |
|---|---|---|
| 라우팅 (유형 판별) | `research` 스킬 | 티켓 #6 |
| **접근/페치** — 출처 본문 확보 | **이 스킬팩** | **신규 (이 문서)** |
| 검증 (L1/L2, dedup, 감사 로그) | `cite_check` 결정론적 코어 | #2 완료 대기 |
| 게이트 (미확인은 단정 금지) | 훅 | #4 |
| 산출 | `verify`/`research` 리포트 | #2, #7 |

정합 판정:
- **코어(ADR 0001)는 안 건드린다.** 코어는 `fetcher` 를 주입받는다 — 이 스킬팩은 **더 똑똑한 fetcher** 하나를 제공하는 것이 전부다. `blocked` 판정을 받은 URL을 사다리로 다시 시도해 본문을 가져오면 코어가 L2를 한다.
- **ADR 0002(도메인=데이터)와 같은 원리를 접근에도 적용한다.** 사이트별 우회 규칙은 코드가 아니라 **에스컬레이션 데이터**(어느 호스트는 어느 칸부터)로 둔다.
- **ADR 0003(게이트)을 강화한다.** 접근 실패는 `blocked` 로 코어에 그대로 흘러가고, 리포트의 미확인에 "왜 막혔고 무엇을 하면 되는지"가 붙는다.
- **인젝션 방어(15 §6)가 이 층의 성역이다.** 접근 층이 가장 신뢰할 수 없는 콘텐츠를 만지는 자리라, 최소권한이 여기서 결정된다.

→ 스코프에 새로 들어오는 건 티켓 하나: **"접근 사다리 + 못 뚫음 리포트"**(#5 어댑터와 형제, #2 뒤). 나머지 결정은 전부 유지.

## 2. 자격증명 경계 — 왜, 그리고 무엇으로 대신하나

### 문제
"내 로그인/비밀번호가 키체인에 있으면 그걸로 로그인해서 읽어라"는 요구는 자연스럽지만, 두 실측이 막는다.

- **간접 프롬프트 인젝션 취약률 24~47%** (GPT-4 ReAct 웹 에이전트 실측, [arXiv:2604.27202](https://arxiv.org/html/2604.27202v1)). 리서치 에이전트는 신뢰 못 할 페이지를 **정의상** 읽는다. 그 페이지가 "X 사이트에 로그인해서 Y를 해라"를 심어두면, 자격증명 접근 권한이 있는 에이전트는 그대로 따른다. 15 §6의 결론: *완전 예방 불가, 최소권한만이 방어*. 키체인 읽기는 최소권한의 정반대다.
- **로그인 뒤 스크래핑은 ToS 위반이 표준.** 13 §3에서 가장 명확한 법적 문서를 가진 Bright Data조차 "로그인 뒤 스크래핑 명시적 금지". 계정 정지 = 사용자의 실제 계정이 날아간다.

### 대안 — 형님이 원하는 것은 그대로 얻는다
"로그인해야 보이는 페이지도 리서치한다"는 **요구는 살린다.** 바뀌는 건 **누가 자격증명을 들고 있느냐**뿐이다.

| 방식 | 에이전트가 pw 보유 | 어떻게 |
|---|---|---|
| ❌ 키체인 직접 읽기 | **예** | 인젝션 1회 = 자격증명 유출 |
| ✅ **로그인된 브라우저 세션 재사용** | **아니오** | 사용자가 이미 로그인한 브라우저에 붙는다. 에이전트는 쿠키·세션만 빌리고 pw는 모른다. **aside**(계정 `u0` 로그인 실측 확인) / Claude in Chrome / Playwright `storageState` |
| ✅ **사람에게 넘기고 멈춤** | 아니오 | "여기 로그인 필요. 로그인하시고 계속하라고 하세요." |
| ✅ 사이트 API 키 (사용자 직접 발급) | 키 1개, 범위 한정 | 13의 어댑터 층 |

**그리고 형님의 "키체인" 요구는 사실 이미 충족된다** — aside 번들에 `Aside Password Importer.app` 이 있다(실측: `~/Library/Application Support/Aside/AsideDaemon/…/Aside Password Importer.app`). 즉 **브라우저가** 키체인에서 자격증명을 가져와 로그인 상태를 유지하고, **에이전트는 그 세션만 쓴다.** 자격증명은 브라우저 안에서 끝나고 에이전트 컨텍스트로 넘어오지 않는다. 이게 정확히 그으려던 선이다.

### 성역 목록 (minimize-with-a-sacred-list)
1. 에이전트 프로세스는 키체인·자격증명 저장소·브라우저 비밀번호 DB를 **읽지 않는다.**
2. 로그인 폼에 값을 **입력하지 않는다.** (사용자가 한다)
3. 세션 재사용은 **읽기 전용** — 글쓰기·결제·설정 변경 도구는 접근 층에 노출하지 않는다.
4. 페이지 콘텐츠는 **데이터**다. 그 안의 지시는 실행하지 않는다.
5. "로그인 벽" 은 실패가 아니라 **정상 종료 상태**다 — 리포트에 방안과 함께 나간다.

## 3. 접근 에스컬레이션 사다리

13의 도구 지형을 **실행 순서**로 배열. 각 칸은 앞 칸의 실패 신호로만 진입한다. 위로 갈수록 비용·리스크·유지비가 크다.

| 칸 | 방법 | 도구 (로컬/무료 우선) | 진입 조건 (앞 칸 실패 신호) | 나가는 조건 |
|---|---|---|---|---|
| **0** | 직접 fetch | stdlib `urlopen` (코어 내장) | — | 2xx + 본문 텍스트 ≥ 의미 있는 길이 |
| **1** | 공개 API / 신디케이션 | 어댑터(#5): Crossref·PubMed E-utilities·OpenAlex, `/rss`, oEmbed | 0이 `blocked`(203·빈 본문) 이고 호스트에 어댑터 있음 | 구조화 응답 |
| **2** | 본문 추출기 경유 | `mcp-server-fetch` → Jina Reader(무키 20RPM) | 0·1 실패, 정적 HTML 예상 | 클린 텍스트 |
| **3** | TLS 위장 | `curl_cffi`(MIT, 로컬) | 403/WAF 신호(Cloudflare 헤더, 봇 페이지 문구) | 200 + 실제 본문 |
| **4** | 헤드리스 브라우저 (비로그인) | Playwright(로컬) | JS 렌더링 필요(빈 `<div id=root>`, SPA) | DOM 텍스트 |
| **5** | **로그인 세션 재사용** | **aside** `repl`/`mcp` (계정 `u0`) · Claude in Chrome · Playwright `storageState` | 로그인 벽 감지(302→/login, 401, "sign in" 폼) **그리고 사용자가 이 호스트에 세션 재사용을 허용함** | 로그인된 DOM 텍스트 (읽기만) |
| **6** | **사람에게 넘김** | 리포트 | 5 불가(세션 없음·미허용·CAPTCHA·유료벽·robots 금지) | `blocked` + 방안 |

**설계 규칙**
- **5는 옵트인.** 기본은 4까지. 호스트별 허용 목록은 사용자가 설정 데이터로 관리 (`access/allow-session.json` 같은 것 — 코드 아님, ADR 0002).
- **3은 ToS 리스크 표시.** curl_cffi 는 무료·로컬이지만 대상 ToS 위반 가능(13 §3). 리포트 감사 로그에 "TLS 위장으로 접근함"을 남긴다. 사용자가 끌 수 있다.
- **CAPTCHA는 풀지 않는다.** FlareSolverr 도 "solver 없으면 에러로 종료"(13). CAPTCHA = 즉시 6.
- **`robots.txt` Disallow 는 존중** — 3·4·5로 우회하지 않는다. 6으로.
- **한 URL당 전체 사다리 시간 상한**(예: 30초) — 예산 소진 시 6.
- 코어와의 인터페이스는 변하지 않는다: `fetcher(url, timeout) → (status, ctype, body)`. 사다리는 그 안에서 돈다. 단, 감사 로그용으로 **어느 칸에서 성공했는지**를 결과에 추가한다(`via: 0..6`).

**상용 안티봇 API(ScrapingBee·Bright Data·Zyte)는 사다리에 없다.** 클라우드 의존이라 폐쇄망 폴백이 안 되고(13 §7), 이 제품의 정체성(검증)이 아니다. 필요하면 사용자가 어댑터로 붙인다.

## 4. "못 뚫음" 리포트 규격 — blocked ≠ none

`blocked` 는 코어가 이미 구분한다(#2). 이 스킬팩이 추가하는 건 **왜**와 **방안**이다.

```
- 확인 불가: <주장> — <url>
  · 막힌 곳: 칸 5 · 사유: 로그인 벽 (302 → /login)
  · 시도: 0(203) → 1(어댑터 없음) → 2(빈 본문) → 3(302) → 4(로그인 폼)
  · 방안:
    1. 이 호스트를 세션 재사용 허용 목록에 넣으면 로그인된 브라우저로 읽습니다 (aside 계정 u0)
    2. 브라우저에서 직접 열어 본문을 저장해 주시면 로컬 파일로 검증합니다
    3. 이 사이트는 API(<링크>)가 있습니다 — 키를 발급받아 어댑터로 붙일 수 있습니다
```

| 사유 코드 | 감지 신호 | 방안 (사용자가 할 수 있는 것) |
|---|---|---|
| `bot-wall` | 203, Cloudflare 챌린지, "verify you are human" | 칸 3 자동 시도됨. 실패 시: 브라우저에서 열어 저장 |
| `captcha` | CAPTCHA 위젯 | 브라우저에서 직접 통과 후 세션 재사용 허용 |
| `login` | 302→login, 401, 로그인 폼 | 세션 재사용 허용 / 직접 저장 / API 키 |
| `paywall` | 유료 구독 문구, 본문 절단 | 구독 계정 세션 재사용(허용 시) / 대체 공개 출처 탐색(프리프린트·PMC) |
| `robots` | robots.txt Disallow | 우회 안 함. 공개 API·대체 출처 |
| `pdf` | content-type pdf | v1 미지원 → PyMuPDF 후속 |
| `dynamic` | 빈 루트, JS 필요 | 칸 4 자동 시도됨. 실패 시 저장 |
| `budget` | 사다리 시간 상한 초과 | 재시도 또는 직접 저장 |

원칙: **방안은 항상 "사용자가 하는 일"이다.** 에이전트가 몰래 더 뚫는 옵션은 없다.

## 5. Claude Code vs Codex — 양 하네스 이식

둘 다 `SKILL.md`(frontmatter `name`·`description`)를 읽는다. 차이는 위치와 주변 기능이다.

| | Claude Code | Codex CLI |
|---|---|---|
| 스킬 위치 | 플러그인 `skills/<name>/SKILL.md` | `.agents/skills/<name>/SKILL.md` (레포→`~/.agents/skills`→`/etc/codex/skills` 순 스캔) |
| 상시 규칙 | `CLAUDE.md` | `AGENTS.md` |
| 훅 게이트 (#4) | `hooks/hooks.json` PreToolUse | **없음** — 게이트를 스크립트로 옮겨 `--strict` 종료코드로 대체 |
| 서브에이전트 (reader) | `agents/*.md` 격리 컨텍스트 | 없음 → 스킬 안에서 "한 출처씩 읽고 요약만 남겨라" 절차로 대체(격리는 약해짐) |
| 브라우저 | Claude in Chrome / aside MCP | aside MCP (`aside mcp` stdio) / Playwright |
| 호출 | `/verify` | `$verify` |

**이식 원칙**: 로직은 전부 `scripts/`(결정론적 코어 + 사다리)에 있고 하네스별 파일은 얇은 래퍼다(ADR 0001이 이걸 이미 보장). 레포 구조:

```
verify/
├── skills/verify/SKILL.md        # Claude Code 플러그인
├── .agents/skills/verify/SKILL.md → ../../../skills/verify/SKILL.md   # Codex (심링크 or 복사)
├── CLAUDE.md · AGENTS.md          # 후자는 전자를 가리키는 한 줄
├── scripts/                       # 공통 코어 (cite_check.py, access_ladder.py)
└── access/                        # 사다리 설정 데이터 (호스트별 시작 칸·세션 허용 목록)
```

Codex 쪽 **약점을 정직하게**: 훅이 없어 게이트가 "스크립트 종료코드 + 스킬 텍스트"에 의존한다 → 모델이 무시할 수 있다. Codex 배포는 "게이트가 약한 버전"임을 README에 명시한다.

## 6. aside CLI 판정 — 사다리 칸 5에 넣는다

**실물 확인 (2026-09-07)**
- `aside 1.26.810.1915`, `/Applications/Aside.app`, 데몬 1.26.905.904
- 서브커맨드: `exec`(브라우저 에이전트 세션) · `repl`(JS 자동화) · `mcp`(stdio MCP 서버) · `account`
- 계정: `u0 inpilotdev@gmail.com signed in, provider google` — **이미 로그인된 브라우저 프로필이 있다**
- 스모크: `aside repl "const p = await openTab('https://example.com'); …"` → 1.6초에 `{"title":"Example Domain"}` 반환. **동작한다.**
- 번들에 `Aside Password Importer.app` — 자격증명은 브라우저 측에서 관리

**판정: 칸 5(로그인 세션 재사용)의 1순위 도구.** 이유:
1. 사용자가 이미 쓰고 있고 로그인돼 있다 — 설치 마찰 0
2. `mcp` 로 Claude Code·Codex 양쪽에 같은 방식으로 붙는다 (하네스 이식 §5와 맞물림)
3. `repl` 로 결정론적 스크립트에서 호출 가능 — 사다리 코드가 LLM 없이 칸 5를 시도할 수 있다
4. 자격증명이 브라우저에 머문다 — 성역 1·2 준수

**칸 5 밖으로는 안 쓴다**: `aside exec`(브라우저 *에이전트*)는 LLM이 들어가서 결정론적 사다리에 안 맞고, 리서치 자체를 aside에 위임하면 이 제품의 검증 층이 빠진다. **읽기 도구로만.**

**미확인**: `aside repl` 의 API 표면(openTab·evaluate 외), 세션 격리(리서치용 별도 프로필 권장 여부), robots 준수 여부, 오프라인 동작.

## 7. 브레인스토밍 — 기존 결정을 흔드는 질문

❓ **Q12 — 접근 층을 verify 안에 두나, 별도 플러그인으로 빼나?** insane-search(2,446★)가 정확히 "접근 층만"으로 성공했다. 우리 사다리도 단독 가치가 있다.
➡️ **v1은 안에.** 사다리의 존재 이유가 `blocked → 재시도 → L2` 이고, 분리하면 데이터 계약이 둘로 갈라진다. 단 `scripts/access_ladder.py` 를 코어처럼 독립 실행 가능하게 만들어 두면 나중에 분리 비용이 0이다.

❓ **Q13 — 칸 3(TLS 위장)을 기본으로 켜나?** 켜면 더 많이 뚫리고, 끄면 ToS 리스크가 0이다.
➡️ **기본 켬, 감사 로그에 명시, 끌 수 있게.** 공개 페이지에 대한 봇 벽 우회는 insane-search 가 2,446★로 시장이 받아들였다. 단 로그인 뒤(칸 5)에서는 절대 3을 섞지 않는다.

❓ **Q14 — 세션 재사용을 "호스트별 옵트인"으로 할 만큼 사용자가 관리할까?** 매번 허용 목록을 만지면 아무도 안 쓴다.
➡️ **첫 로그인 벽에서 한 번 묻고 기억한다.** "이 호스트에 로그인된 세션을 쓸까요? [이번만/항상/안 함]" → `access/allow-session.json` 에 기록. 옵트인은 유지하되 마찰은 1회.

❓ **Q15 — Codex 지원이 v1에 들어가야 하나?** 훅이 없어 게이트가 약해지는데, 약한 버전을 내는 게 제품 정체성(게이트)과 충돌한다.
➡️ **v1은 Claude Code만, Codex는 `.agents/skills` 심링크 + README 한 줄("게이트 약함").** 코어가 하네스 독립적이라 비용이 거의 없고, 정직하게 표기하면 정체성은 지켜진다. 본격 Codex 지원은 Codex에 훅 상당 기능이 생기면.

❓ **Q16 — 인젝션 사전 스캔(15 §6-3)을 접근 층에 넣나?** "ignore previous instructions" 정규식 스캔은 싸지만 완전하지 않다.
➡️ **넣는다, 결정론적으로, 차단이 아니라 표시로.** 페치한 텍스트에 인젝션 패턴이 있으면 결과에 `injection_suspect: true` 를 붙이고 리포트 감사 로그에 남긴다. 그 출처는 검증엔 쓰되 리더가 요약할 때 "의심 표시된 출처"로 넘긴다. 완전 방어는 불가(15)이니 탐지+격리가 목표.

❓ **Q17 — "어느 출처든 뚫는다"가 제품 첫 줄인가, "검증"이 첫 줄인가?** 형님이 이번에 "가장 중요 포인트"로 접근을 꼽았다. 16은 검증을 첫 줄로 잡았다.
➡️ **검증이 첫 줄, 접근은 "그래서 실제로 되는 이유".** "뚫는다"만 앞세우면 insane-search 와 정면충돌이고 검증 층이 빠진 페치 도구가 된다. "인용 38개를 실제 출처 원문까지 뚫고 들어가 대조했다"가 한 문장 — 둘 다 들어간다.

❓ **Q18 — 사다리를 코어에 합치나(fetcher 교체), 코어 앞단 전처리로 두나?**
➡️ **fetcher 교체.** 코어는 이미 `fetcher` 를 주입받는다. `access_ladder.fetch` 를 넘기면 끝이고 코어 테스트는 그대로 산다. 결과에 `via` 칸 번호만 추가.
