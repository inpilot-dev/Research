# 종합 — "신뢰성 있는 리서치 에이전트"를 어떻게 만들 것인가

병렬 조사 5스트림(11~15) + 선행 조사(00~10)를 하나의 설계로 묶는다.

## 0. 한 줄

리서치 에이전트의 제품은 "검색해서 요약"이 아니라 **신뢰성을 강제하는 파이프라인**이다.
그 신뢰성은 세 조사가 독립적으로 같은 곳을 가리켰다 — 인간 전문가의 검증 규율(11), 아키텍처가 실제로 신뢰성과 상관있던 선택(12), 그리고 에이전트가 신뢰성을 잃는 지점(15). 이 셋의 교집합이 곧 설계도다.

---

## 1. 세 조사가 만난 지점 — 신뢰성의 척추(spine)

세 문서가 서로 다른 출발점에서 **같은 5개 원리**로 수렴했다. 이게 우연이 아니라서 설계의 뼈대로 쓴다.

| 원리 | 인간 규율(11) | 아키텍처 근거(12) | 실패 방어(15) |
|---|---|---|---|
| **① 독립성 검증** (여러 출처 ≠ 여러 확인) | 순환보고 계보 추적, 2-source 원칙 | — | dedup·순환보고 방어(2) |
| **② 원문 대조** (주장을 원 맥락까지) | Trace claims, 1차 출처 추적 | 출처 품질 휴리스틱 명시 | 인용 fetch+텍스트 대조(1) |
| **③ 감사 가능성** (판정 절차를 기록) | PRISMA 검색·제외 로그 | LLM-judge 5기준+인간검토 | 불확실성 표기 강제(4) |
| **④ 신뢰도≠사실** (두 축 분리) | Admiralty Code 6×6 | — | authority 스코어링(5) |
| **⑤ 반증 지향** (선호결론 반대편 탐색) | ACH, early-narrowing 방지 | 넓게 훑고 좁히기 | 데이터공백 과대표집 방어 |

그리고 **6번째 축은 인간 규율에 없다** — 15가 새로 지목: **간접 프롬프트 인젝션**(retrieved 페이지가 "이전 지시 무시"를 심음). 정보 오류가 아니라 **보안 침해**라 최소권한+데이터/지시 채널 분리로만 막는다. 리서치 에이전트가 웹을 읽는 순간 이 위협이 상시 존재한다.

---

## 2. "전체를 아우른다"의 실체 — 도메인 스킬이 아니라 라우팅

사용자 요구("리서치 하는 사람 전체")를 14가 분류학으로 풀었다. 핵심: **리서치 종류마다 '신뢰성'의 뜻이 다르다.**

| 유형 | 신뢰성의 뜻 | 검증 깊이 |
|---|---|---|
| 빠른 팩트 | 정확성(값 수렴) | L1 + 계산엔진 |
| 학술 문헌 | 검증 가능성(DOI 추적) | L2 + 철회 확인 |
| 시장/경쟁사 | 최신성 + 1차/2차 구분 | 시점 병기 |
| 실사(기업·법적) | 법적 무결성 | 원본 공적기록 |
| 시사/뉴스 | 시점 고정 + 정정 추적 | 통신사 원발 |
| 기술/API | 버전 일치 | changelog 대조 |
| 제품 비교 | 이해상충 부재 | 무제휴 매체 |
| 탐색적 학습 | 지형 파악 | 위키는 입구만 |
| 데이터/통계 | 방법론 투명성 | 공식 포털 정의 |

→ **"전체를 아우르는 에이전트" = 질문을 유형으로 판별해 신뢰성 기준·출처 화이트리스트·검증 깊이를 갈아 끼우는 라우터.** 도메인마다 스킬을 만드는 게 아니다(05·06이 이미 기각). 애매하면 **가장 엄격한 유형(실사)의 기준을 기본값**으로 — 신뢰성은 아래로 완화 없이 위로만 합산.

이게 앞선 결정과 어떻게 이어지나: **의학 NCT 대조는 "유형 2(학술)+유형 4(실사)의 프리미엄 검증 모듈"**로 격하된다 — 제품 전체가 아니라, 식별자가 강한 유형에서만 켜지는 심층 검증 하나. 사용자의 "논문 하나에 가둬지지 말자"와 정확히 일치.

## 3. 아키텍처 — 12가 검증한 것만 이식

12에서 **신뢰성과 실제 상관있다고 원문이 뒷받침한** 선택만 골랐다(자기보고 성능 자랑은 버림).

- **오케스트레이터 + 병렬 서브에이전트**, 단 "읽기중심·병렬가능·큰 컨텍스트"인 조사 작업에만. 쓰기/의존성 작업은 순차 단일. (Anthropic+LangChain 일치)
- **서브에이전트 위임 4요소 강제**: 목표·출력형식·도구/출처 가이드·경계. (없어서 실패한 사례가 원문에 있음)
- **컨텍스트 격리**: 원문 대량 읽는 리더와 종합하는 라이터를 분리, 압축 요약만 위로. (05 Scriptorium의 데이터 계약과 같은 결론)
- **종료조건 = 하드캡 + 예산 소진.** 신뢰도 임계값 종료는 업계 표준 미확인 → 우리 eval로 직접 튜닝.
- **비평/토론은 만능 아님.** 넣으려면 비평자에게 다른 역할/기준을 명시하고, "고립된 자기교정 대비 실제 개선"을 자체 eval로 검증한 뒤에만.
- **모델 교체가 아키텍처보다 큰 지렛대일 수 있음.** 구조 정교화 전에 기반 모델 업그레이드 개선분을 먼저 측정.

## 4. 파이프라인 (신뢰성 게이트를 박은 형태)

```
질문
 → [분류] 유형 판별(14) → 신뢰성 기준·출처 화이트리스트·검증 깊이 세팅
 → [계획] 넓게 훑고 좁히기(early-narrowing 방지), 하위질문 분해
 → [수집] 병렬 리더 서브에이전트, 유형별 화이트리스트 우선(13 스택)
 → [검증] ── 신뢰성 척추 ──
     ① 순환보고 dedup → "N개 확인"을 unique publisher로 교정
     ② 인용 fetch + 원문 텍스트 대조(L1 존재 → L2 문자열/퍼지 매칭)
     ③ authority 스코어링(어필리에이트·AI생성 의심·저자정보·1차/2차)
     ④ 신뢰도축 ≠ 사실축 분리 기록
     ⑤ 반증 근거 능동 탐색
 → [종합] 근거 강도에 비례한 불확실성 표기 [주장–신뢰도–근거수–상충]
 → [산출] 감사 로그(검색 N·채택 M·제외 사유) 동봉
```

**보안 레인(상시)**: 리서치 에이전트는 읽기 전용. 검색 결과는 **데이터 채널로만** 취급하고 지시로 실행하지 않음. 아웃바운드 행동 전 목표 정합성 재확인. (15-⑥)

**결정론 우선**: ①②는 LLM 없이 코드로 가능(URL 생존, 문자열/퍼지 매칭, 게시일, 도메인 신뢰도). L3(의미적 뒷받침, entailment)에서만 LLM. → 05·07의 "로직은 scripts/에, 스킬은 얇은 래퍼" 구조와 그대로 맞물림. 검증이 LLM 밖에 있어야 재현·테스트·현장 시연이 된다(nagomi "GRADE" 실패의 반대편).

## 5. 접근 도구 스택 (13, 무료/오프라인 우선)

사용자 폐쇄망·Ollama 폴백 전제. **검색만 클라우드 불가피**, 나머지는 오프라인 내성 최대화.

- 검색: Tavily(월 1,000 무료) 또는 Brave($5 크레딧). Google PSE는 2027-01 종료라 신규 배제.
- 본문추출: `mcp-server-fetch`(로컬) → Jina Reader(무키 20RPM) → trafilatura(원본 HTML 있으면 네트워크 불필요).
- 동적 페이지: Playwright(로컬, storageState).
- PDF: PyMuPDF → marker/docling → 학술은 Grobid(로컬).
- 차단 대응 필요할 때만: curl_cffi/FlareSolverr(로컬). 상용 안티봇 API는 클라우드 의존이라 폴백 부적합.
- 폐쇄망: **사전 크롤링해 로컬 캐시**가 유일한 실질 대응 — 이후 파이프라인은 오프라인 완결.

insane-search는 이 스택에서 "차단 대응" 한 칸일 뿐 — 한 툴에 매몰될 이유 없음(사용자 지적대로). 페치는 escalation 사다리의 마지막 단계다.

## 6. 앞선 결정과의 정합

| 항목 | 이전 | 이번 조사 반영 |
|---|---|---|
| 제품 정체성 | 인용 검증(좁게) | **신뢰성 파이프라인**(라우팅으로 전체 리서치 아우름) |
| 도메인 | 의학 앵커 | 의학 NCT = 유형2+4의 **프리미엄 모듈 1개**로 격하 |
| 배포 형식 | 플러그인 | 유지(03). 로직은 scripts/, CLI 실사용 = argparse 하나(07) |
| 2층 구조 | 작업/어댑터 | 유지·강화 — 어댑터 = 유형별 출처 화이트리스트 |
| MCP | 안 만듦 | 유지. fetch는 mcp-server-fetch 기존 것 사용 |

## 7. 열린 결정 (다음 라운드)

1. **v1 범위** — 전 유형 라우팅을 다 넣나, 아니면 2~3유형(예: 학술+기술문서+팩트)으로 시작해 라우터만 확장 가능하게? (권장: 후자 — 05가 "얇게 시작" 지지, 라우팅 골격은 처음부터)
2. **검증 깊이 기본값** — L2(원문 텍스트 대조)를 v1 기본으로? L3(entailment)는 옵션? (권장: L2 기본, L3는 flag)
3. **이름** — `skills find`가 이름 부분일치. `verify`/`research`/`grounded` 계열 짧은 일반명사.
4. **npj 논문 확인** (08의 🔴) — outcome-switching 자동탐지 인접 연구, 착수 전 본문 확인 필요.
5. **eval 세트** — 12가 "20개 대표 쿼리 + LLM-judge 5기준 + 인간검토"를 권고. 유형별 대표 쿼리를 먼저 만들 것.
